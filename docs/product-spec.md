# 时块 BlockFlow · 产品规格（Product Spec）

> 版本：Stage 0 基线 · 状态：已评审（对应现有原型 v2 数据结构）
> 本文档是产品定义，不描述实现细节。实现细节见 `data-model.md`、`scheduling-rules.md`、`timer-rules.md`。

## 1. 一句话定义

把用户输入的「一件事或多件事」安排到具体时间块里，直接告诉用户**几点到几点做什么**；用户不填时长时自动估算；任务中途发生变化时，根据已完成进度**重新安排剩余任务**。

## 2. 定位与非定位

| 是 | 不是 |
| --- | --- |
| 输入任务 → 输出具体时间块的排程器 | 普通待办清单（只管「要做什么」） |
| 会因进度、中断、变动而重排的动态计划 | 固定日历（只能手动摆位置） |
| 移动端优先、可离线运行的本地应用 | 云端协作 / 账号系统 |

## 3. 目标用户与使用场景

- 需要在一天内把若干件事排出先后顺序的个人用户。
- 典型场景：早上输入今天要做的 3–5 件事，得到「9:00–9:30 做什么、接下来做什么」的时间线；做到一半被打断后，让系统重新安排剩余内容。

## 4. 功能范围（第一版必须支持）

1. **单任务输入**：一次输入一个任务。
2. **多任务输入**：一次输入多行，每行一个任务。
3. **用户指定任务时长**：用户填写目标时长（分钟）。
4. **自动估算时长**：用户不填写时，由系统给出默认估值（估算规则见 `scheduling-rules.md`）。
5. **日期选择**：今天、明天、未来任意日期。
6. **三种安排方式**：自由安排、偏好时间、固定时间。
7. **重复规则**：每天、工作日、每周同一天；自定义重复列入后续版本。
8. **基础时间约束**：睡眠、吃饭（早/午/晚）、上课/通勤等以固定时间表示。
9. **时间线生成**：自动生成「几点到几点做什么」。
10. **固定时间保护**：固定时段只能放指定任务，其他任务必须避开。
11. **超出固定时段的补排**：目标时长 > 固定时段时，剩余部分排到当天其他空档。
12. **执行控制**：开始、暂停、继续、记录中断、完成。
13. **计时恢复**：切换应用、锁屏、关闭页面后重新打开仍能恢复计时。
14. **长时间离开询问**：离开超过阈值时，询问离开时间是否计入任务。
15. **进度备注**：记录进度备注与「下次继续位置」。
16. **突发情况重排**：发生变故后重新安排剩余任务。
17. **时间不足方案**：当天时间不够时，明确提供缩短、顺延、调整三种方案。
18. **复盘与历史**：每日复盘、历史记录、设置。

## 5. 各功能的产品定义

### 5.1 输入与估时

- 用户在「新建任务」页输入，每行一个任务；可批量填写对应时长。
- 未填写时长时，系统按任务文本自动估算（默认估值），并在界面上标注这是「估算值」，用户可随时编辑为准确值。
- 时长单位为分钟，最小粒度 5 分钟。

### 5.2 日期

- 三个快捷入口：今天、明天；其余通过日期选择器选择。
- 固定时间任务可跨日期生效（受重复规则影响）；自由/偏好任务绑定在具体日期。

### 5.3 安排方式

- **自由安排**：系统从当天可用时间中自动寻找空位，按顺序填充，互不重叠。
- **偏好时间**：优先放在用户给定的开始时间；被固定时段或用餐占用时自动顺延，不抢占。
- **固定时间**：锁定开始–结束时段（24 小时制）；该时段不可被其他任务占用。

### 5.4 时间约束（睡眠 / 吃饭 / 上课 / 通勤）

- 睡眠：作为当天不可用的边界，容量从「起床时间」到「入睡时间」。
- 吃饭：早/午/晚各占一段，作为固定占用，其他任务必须避开。
- 上课 / 通勤：以「固定时间任务」的形式表达，等同固定时段处理。
- 任何约束都**不能被静默占用或覆盖**：冲突时必须显式提示。

### 5.5 时间线与补排

- 输出为有序时间块列表，每块含开始、结束、所属任务、是否固定、是否为补排段。
- 固定时段放不下的剩余目标时长（补排段）自动出现在当天其他空档。

### 5.6 执行与中断

- 状态：待开始 → 进行中 ⇄ 已暂停 → 已完成。
- 支持暂停、继续、记录中断；中断需记录次数与时段。
- 完成时记录实际时长，并与计划时长对比进入复盘。

### 5.7 恢复与离开询问

- 计时基于时间戳而非页面存活，关闭/锁屏/切后台后重新打开可恢复。
- 暂停离开超过阈值（默认 15 分钟）时，提示离开时长，并**询问是否计入任务**（计入 / 不计入）。

### 5.8 重排与时间不足

- 突发情况：支持对「未开始/未完成」的剩余任务重新生成时间线。
- 已完成进度视为既定事实，重排时不可被覆盖。
- 当天容量不足时，给出三种可选方案：缩短任务、顺延到次日、调整安排方式/时间，由用户确认。

### 5.9 复盘、历史、设置

- 复盘：计划时长、实际时长、中断次数、顺延总量、逐任务对比。
- 历史：按日期查看过往计划与执行情况。
- 设置：睡眠、三餐、休息缓冲、离开提醒阈值、估算偏好、数据导入导出/清空。

## 6. 第一版明确不做

- 不做账号系统、云同步、多人协作。
- 不做小程序、原生 App、后端服务、数据库。
- 不接入任何外部 AI API、不联网。
- 不做拖拽排序（第一版按开始时间排序）。
- 不做自定义重复的完整编辑器（仅每天 / 工作日 / 每周同一天）。
- 不做通知推送、日历订阅、第三方导入。
- 不提供学习、健身、饮食、医疗等任何领域性建议（见第 8 节边界）。

## 7. 技术形态（第一版）

- HTML5 + CSS3 + 原生 JavaScript（ES6），移动端优先的响应式 Web 应用。
- 无 npm 依赖、无框架、无后端、无数据库、无 Docker、无云服务。
- 数据全部保存在浏览器 `localStorage`，键名 `blockflow.v1`。
- 双击 `index.html` 即可在 `file://` 下运行，预览无需安装依赖。
- PWA 文件为可选项，且不得影响 `file://` 直接运行。

## 8. 绝对边界（产品红线）

1. 不添加英语学习方法建议。
2. 不添加健身动作、训练指导或运动处方。
3. 不添加饮食、医疗和健康建议。
4. 不做账号系统、云同步和多人协作。
5. 不做小程序、原生 App 或后端服务。
6. 不在代码中写 API Key。
7. 不把用户数据发送到任何外部服务。
8. 固定时间不能被其他任务自动占用。
9. 已完成的进度不能被重新排期覆盖。
10. 不能静默删除、丢失或隐藏任务。
11. 不能把失败伪装成成功，任何失败必须可见。

> 注：示例任务中出现「英语」「跑步」等字样仅作为**任务名占位**，不代表任何学习方法或运动指导。

## 9. 产品验收标准（端到端）

1. 双击 `index.html` 可直接打开并操作，无控制台报错。
2. 单任务、多任务均能添加并生成时间线。
3. 不填时长时任务有估算时长且可被编辑。
4. 今天 / 明天 / 未来日期均可切换并生成对应时间线。
5. 自由、偏好、固定三种安排方式行为符合第 5.3 节。
6. 每天 / 工作日 / 每周重复任务在对应日期出现。
7. 固定时段不被其他任务占用；冲突时给出可见提示且不覆盖。
8. 目标时长超出固定时段时，剩余部分出现在其他空档。
9. 开始 / 暂停 / 继续 / 记录中断 / 完成状态流转正确。
10. 刷新或重开页面后计时可恢复。
11. 离开超过阈值有提醒与询问。
12. 复盘统计与实际执行一致。
13. 空状态与错误均有明确提示，且提示滚动到可见区域。
14. 375px 与 ≥960px 下布局均正常。
15. 所有数据仅存于本机 localStorage。
