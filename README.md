# 时块 BlockFlow

移动端优先的响应式时间块管理 Web 应用。中文界面，纯 HTML + CSS + 原生 JavaScript，无任何依赖、后端或数据库。

## 特性

- **今日**：日期切换、时间线、任务列表、剩余可用时间。
- **新建任务**：一次输入多个任务（每行一个），可批量指定时长，支持三种「安排方式」。
- **编辑任务**：在任务列表点「编辑」可再次修改名称、目标时长、日期与安排方式。
- **固定时间**：按 24 小时制锁定时段，其他任务不会占用；目标时长超出固定时段时自动补排。
- **执行**：显示当前任务、正向计时与剩余时间，暂停 / 继续 / 记录中断 / 完成，可记录进度备注与「下次继续位置」；锁屏或切到后台后返回，会按离开时长弹出「是否计入任务」的确认。
- **复盘**：八项统计（计划/实际总时长、完成率、计划偏差、中断次数、中断总时长、顺延总时长、完成任务数）、状态分布、完成率条与任务卡片（提前/按时/超时判定），支持按状态筛选。
- **历史**：按日期倒序查看最近有任务的日期列表（计划/实际/完成率/任务数），点击查看当天完整任务、实际用时、中断、顺延与进度备注。
- **设置**：睡眠、吃饭、休息缓冲、离开确认阈值（1–60 分钟）、固定占用（上课 / 通勤等）。
- **数据导入 / 导出**：设置页可将全部数据导出为 JSON 备份，也可从 JSON 文件导入（导入前校验格式、覆盖前二次确认，全程本地、不经云端）。
- **安装到桌面（PWA）**：通过 http/https 访问时可安装为桌面 / 主屏幕应用并离线打开；`file://` 直接打开仍完全可用。

数据全部保存在浏览器 `localStorage`，键名为 `blockflow.v1`。首次打开会自动写入示例数据，可直接操作。

## 安排方式说明

| 安排方式 | 行为 |
| --- | --- |
| 自由安排 | 系统从可用时间中自动寻找空位，按顺序填充，互不重叠。 |
| 偏好时间 | 优先放在偏好开始时间；若被固定时段或用餐占用则自动顺延，不会强占。 |
| 固定时间 | 锁定指定日期的开始–结束时间（24 小时制，如 `15:00`–`17:00`），并支持重复规则。 |

固定时间的规则：

- 固定时段优先于其他任务，Python、AI 开发、运动等任务会自动避开，不会占用固定时段。
- 任务保留「目标时长」。例如英语固定 `15:00–17:00` 但目标为 3 小时时，`15:00–17:00` 先放入 2 小时并显示「固定」标记，剩余 1 小时自动安排到当天其他空闲时间（时间线与列表中显示为「剩余安排」）。
- 若目标时长小于固定时段长度，只占用目标时长，其余时间不被该任务占用。
- 与已有固定任务或用餐时间冲突时会在「新建 / 编辑」界面给出明确提示，且不会自动覆盖已有时段。
- 固定时间支持重复规则：仅今天 / 每天 / 工作日 / 自定义重复（仅「自定义重复」会显示星期勾选框，其他规则自动隐藏并清空勾选）。
- 固定时间模式下一次只添加一个任务（固定时段无法批量占位）。

## 自动排期规则

排期由统一的 `scheduleForDate(dateKey)` 计算，界面时间线直接使用其结果，保证「看到的时间线」与「实际排期结果」一致：

- **锁定顺序**：先锁定睡眠（起床→入睡为可用容量窗口）、吃饭、固定占用（上课 / 通勤等）与固定任务，再按「偏好任务 → 自由任务」顺序安排。
- **任务缓冲**：任务之间保留 5–10 分钟缓冲（设置中休息缓冲会被钳制到这个范围，设为 0 时按 5 分钟处理）。
- **不能排到过去**：今天的任务不会安排在当前时刻之前；未来日期则从 0 点起算。
- **不占用禁区**：睡眠、吃饭、固定任务与固定占用时间都不会被自由 / 偏好任务占用。
- **不删任务、不覆盖已完成**：当天时间不足时不会删除任务，也不会改动已完成任务的记录，而是在时间线顶部给出「时间不足」面板。
- **时间不足方案**：面板提供「缩短」「顺延（移到次日）」「调整（改为自由 / 偏好）」三种可选方案，由你点击后才会应用并重新排期。
- **自动重排**：在时间规则表编辑 / 替换 / 暂停 / 恢复 / 删除规则，或修改设置、新增任务后，系统会立即对当天未完成任务重新排期（固定任务与已完成任务不受影响）。

## 日期与自动估时

- 「新建任务」可先选日期：今天 / 明天 一键切换，或用日期选择器选任意日期；自由、偏好、固定任务都按该日期安排。
- 目标时长留空时系统按任务内容自动估算（`estimateDuration`），用户填写则以填写值为准；批量时长按行对应，缺省的行再用统一时长或自动估时。
- 自动估算仅为保守估值，可在「今日」列表点「编辑」随时改为准确值。

## 固定占用（上课 / 通勤等）

在「设置」页可维护一类周期性不可用时段——固定占用：

- 每条固定占用包含名称（如「上课」「通勤」）、开始 / 结束时间，以及生效星期（不勾选表示每天）。
- 当日生效的固定占用会并入调度约束：自由 / 偏好任务自动避开，固定任务与其冲突时会被拒绝并给出明确提示。
- 固定占用按日期生效：切换到周一显示「上课 + 通勤」，切换到周日可能只显示「通勤」，无需手动增删。
- 修改后点「保存设置」生效；旧数据没有该字段时按「无固定占用」安全处理。

## 时间规则表

「设置」页的「时间规则表」集中管理所有**固定时间**与**偏好时间**任务，避免逐条回到「今日」修改：

- 每条规则显示：任务名称、类型（固定 / 偏好）、时间、日期、重复规则、自定义星期、当前状态。
- 操作：
  - **编辑**：复用编辑弹窗，修改后更新原任务，不会创建重复任务。
  - **替换任务**：选择一个已有任务或输入新名称，让新任务接管原固定 / 偏好时间；原任务取消约束并改为自由安排（不删除）。
  - **暂停规则 / 恢复规则**：暂停后该任务不再占用固定 / 偏好时间，但任务本身保留、仍可执行。
  - **删除**：二次确认后删除该任务及规则。
- 规则表与「新建」「编辑弹窗」共用同一份 `localStorage` 数据，三处修改后同步更新；刷新页面后规则与状态保留。
- 规则表为空时显示空状态，并提供「新建时间规则」按钮直达新建页。

旧数据（没有「安排方式」字段）会自动按「自由安排」处理，固定字段缺失时也会安全回退，不会报错或白屏。

## 预览方式

### 方式一：直接打开（最简单）

双击 `index.html`，或用浏览器打开该文件即可。所有功能在 `file://` 下均可正常使用。

### 方式二：本地静态服务（推荐）

任选一种（本机已具备 Python）：

```bash
# Python 3
python -m http.server 8080
```

然后在浏览器访问 <http://localhost:8080/>。

也可以使用 Node（无需安装依赖，仅作静态服务）：

```bash
npx serve .
```

## 测试方式

本项目为纯前端应用，没有自动化测试脚本，采用手动验收。建议按下列清单逐项验证：

### 1. 示例数据

1. 首次打开页面，确认「今日」自动出现 4 个示例任务。
2. 刷新页面，确认数据仍然存在（localStorage 生效）。

### 2. 今日

1. 点击 `‹` / `›` 切换日期，日期标签与星期显示正确。
2. 切到其他日期确认显示空状态提示；点右上角按钮回到今天。
3. 时间线按开始时间升序排列，完成的任务呈绿色。

### 3. 新建任务

1. 在文本框每行输入一个任务，点「添加到当天」，确认一次性生成多个任务。
2. 在「批量目标时长」填入 `30,60,180`，确认按行匹配目标时长。
3. 输入为空时点击添加，确认出现红色错误提示且不新增任务。
4. 目标时长输入小于 5 时点击添加，确认提示不合法。
5. 切换「安排方式」，确认自由安排 / 偏好时间 / 固定时间对应的输入框正确显示与隐藏。

### 3.1 固定时间（重点验证）

1. 安排方式选「固定时间」，任务填 `英语`，目标时长填 `180`，开始 `15:00`，结束 `17:00`，日期选今天，点「添加到当天」。
   - 若示例数据中已存在「英语 15:00–17:00」固定任务，会立即弹出提示框并在页面上显示醒目的红色「固定时段已被占用：与固定任务「英语」（15:00–17:00）冲突」提示，任务不会被添加（这是预期行为，不是无响应）。此时把时间改成未被占用的时段，或先删除已有的英语固定任务再试。
   - 若无冲突，点击后表单会被清空、数据写入 localStorage，并自动切到「今日」显示新任务。
2. 在「今日」确认时间线出现 `英语 · 固定 15:00–17:00`，标题带「固定」徽标，且另有一段「剩余安排」（如 `17:00–18:00`），表示超出固定时段的 1 小时被自动排到其他空闲时间。
3. 再把英语目标时长改成 `60` 分钟（用「编辑」修改），确认只占用 `15:00–16:00`，`16:00–17:00` 不再被该任务占用，也没有剩余安排段。
4. 新建 `Python`（自由安排，时长 120）与 `AI 开发`（偏好时间 `15:30`），确认它们都不会落到 `15:00–17:00` 内，而是自动顺延。
5. 再次新建固定任务，把时间设成与「英语」重叠，例如 `16:00–18:00`，确认弹出「固定时段已被占用」提示且任务未被添加。
6. 把固定时间设成与午餐重叠（默认 `12:00` 起 40 分钟），确认提示与午餐冲突。
7. 用「固定示例」按钮可一键填充 `英语 / 180 分钟 / 15:00–17:00`，便于快速复现。
8. 重复规则分别选「每天 / 工作日 / 自定义重复」，切换到对应日期，确认固定任务按规则出现或不出现在时间线上；切到「仅今天 / 每天 / 工作日」时星期勾选框应隐藏并清空，仅「自定义重复」显示勾选框。
9. 保存后刷新页面（F5），确认固定时间、目标时长与剩余安排仍然保留。

> 提示：任何添加失败都不会静默。页面上会出现红色错误块并自动滚动到可视区域，同时弹出提示框，控制台也会打印具体原因。若点击后仍无任何反应，请打开浏览器控制台（F12）查看 `操作失败` 日志并反馈。

### 3.1.1 自动排期（Stage 4 重点验证）

1. 删除示例中的英语任务后，新建固定任务：英语 `15:00–17:00`、目标 `180`；再新建 Python（自由，`120`）、AI 开发（偏好 `15:30`）、运动（自由，`40`）。
2. 切到「今日」确认：英语锁定 `15:00–17:00` 并另有一段「剩余安排」（约 `17:00–18:00`）；AI 开发不会落到 `15:00–17:00` 内；Python 与运动依次向后排且两两间隔 5–10 分钟。
3. 打开 F12 确认无报错。
4. 到「设置 → 时间规则表」把英语编辑为 `16:00–18:00`，保存后回到「今日」，确认时间线整体重新排布（其他任务自动避开新时段）。
5. 在规则表点「暂停规则」暂停英语，确认英语不再独占 `16:00–18:00`，其他任务可排入该时段；点「恢复规则」后再次重排。
6. 重复规则选「自定义重复」并只勾选周一 / 周三 / 周五，切到对应日期确认生效，切到周二确认不出现。
7. 制造时间不足：连续添加多个长任务（如 12 个 120 分钟任务），确认时间线顶部出现「时间不足」面板，列出缩短 / 顺延 / 调整方案；点击其中一个方案，确认任务被相应调整并重新排期。
8. 刷新页面（F5），确认固定时间与「剩余安排」仍然保留、排布一致。

### 3.2 编辑任务

1. 在任务列表点某任务的「编辑」，确认弹窗回填其当前名称、目标时长、日期与安排方式。
2. 把「自由安排」改为「固定时间」并填写合法时段，保存后确认时间线出现「固定」徽标。
3. 把任务日期改到别的日期，保存后确认该任务从原日期消失、出现在新日期。
4. 名称留空或目标时长小于 5 时点保存，确认弹出错误提示且弹窗不关闭。
5. 按 `Esc` 或点「取消」/ 遮罩，确认弹窗关闭且未修改数据。

### 3.3 旧数据兼容

1. 打开浏览器开发者工具 → Application → Local Storage，将 `blockflow.v1` 的值替换为不含 `mode` 字段的旧版任务 JSON。
2. 刷新页面，确认页面正常渲染，旧任务按「自由安排」显示，无报错或白屏。

### 4. 执行

1. 选择一个任务点「开始」，计时器开始走动。
2. 点「暂停」→ 状态变为已暂停；点「继续」→ 恢复计时并记录一次中断。
3. 点「记录中断」，确认中断列表新增一条且总时长被正确扣减。
4. 点「完成」，确认任务变为已完成，执行计时停止。
5. 执行中开始另一个任务，确认前一个任务被自动暂停并提示。
6. **离开确认（Stage 7）**：执行某任务后切到其他应用 / 锁屏，离开时间超过「离开确认阈值」（默认 5 分钟）再返回，页面会弹出「你离开了 X 分钟，这段时间算入「任务名称」吗？」，可选择：
   - **全部计入**：离开区间计入实际用时，并记一条「计入」中断；
   - **全部不计入**：不计入实际用时，从返回时刻继续计时，后续任务自动重新排期；
   - **只计入一部分**：输入 `0 ~ 离开分钟数` 之间的值，仅计入指定时长；
   - **从离开时暂停**：保留离开前的实际用时，任务变为「已暂停」。
7. 离开未超过阈值（如 3 分钟）时不弹窗，计时直接继续。
8. 关闭标签页再重新打开，未确认的离开弹窗会自动恢复；已确认过的不会重复弹出。
9. 执行页状态区会显示「剩余 N 分钟」；中断列表用「计入 / 不计入」标签区分离开是否计入了用时。

### 5. 复盘与历史（Stage 5）

1. 切换到「复盘」，核对八项统计（计划总时长、实际总时长、完成率、计划偏差、中断次数、中断总时长、顺延总时长、完成任务数）与状态分布、完成率条。
2. 卡片状态规则验收：
   - 英语目标 180 分钟、实际约 2 分钟 → 徽章「提前完成」，显示「提前 X 分钟」；目标条 100%、实际条极短，右侧「2 分钟 · 1%」。
   - 目标 30 分钟、未开始 → 「待开始」，不显示时长差。
   - 目标与实际均 60 分钟 → 「按时完成」。
   - 目标 60、实际 90 → 「超时」，实际条保持 100% 且为超时色，显示「超出 30 分钟」。
3. 用筛选栏切换 全部 / 已完成 / 未完成 / 有中断 / 已顺延，确认列表实时过滤；结果为空显示空状态。
4. 在「执行」页对任务添加进度备注与「下次继续位置」，确认复盘卡片与历史详情同步展示。
5. 「历史记录」面板确认有任务日期按日期倒序排列并显示计划/实际/完成率/任务数；点击某天确认日期切换、详情显示当天完整任务与备注。
6. 编辑任务、计时、加备注后回到复盘与历史确认实时更新；删除任务后确认历史统计同步变化；刷新页面确认数据仍在。
7. 无任务日期复盘显示空状态提示。

### 6. 设置

1. 修改睡眠、三餐、休息缓冲、提醒阈值后点「保存设置」，确认提示成功。
2. 入睡与起床时间相同、时长越界时，确认保存被拒绝并给出错误提示。
3. 在「固定占用」点「添加固定占用」，填名称（如「上课」）、`09:00`–`11:00`，只勾选周一，保存。
4. 切到「今日」选一个周一日期，确认时间线上自由任务避开 `09:00–11:00`；选周日日期确认该占用不生效。
5. 新建固定任务并把时间设成与固定占用重叠（如 `09:30–10:00`），确认提示「与固定占用「上课」（09:00–11:00）冲突」且任务未被添加。
6. 点「恢复默认」确认设置回退且任务数据保留。
7. 点「载入示例数据」确认恢复示例；点「清空全部数据」确认清空后进入空状态。

### 7. 响应式与可访问性（Stage 6）

**响应式**
- 用开发者工具依次切换 320 / 375 / 430 / 768 / 1200px 宽度：五页均可操作、无横向滚动条；1200px 下主内容居中（约 1080px）不空洞，768px 下约 760px。
- 底部导航不遮挡最后一张卡片（已预留 `env(safe-area-inset-bottom)` 安全区）。
- 时间线、任务卡、复盘卡、规则表、设置表单、弹窗均不横向溢出；超长任务名自动换行不撑破卡片。

**可访问性**
- 键盘：Tab 可依次聚焦按钮/输入框，焦点有 3px 明显外框；任意位置按 Tab 到「跳到主要内容」可直接跳过导航。
- 弹窗：打开后聚焦弹窗内首个可聚焦元素，Tab 在弹窗内循环（焦点陷阱），按 Esc 关闭且焦点回到触发按钮。
- 按钮/输入框/下拉框均有 `<label>` 或 `aria-label`；筛选按钮与 tab 用 `aria-pressed`/`aria-selected` 暴露状态。
- 错误/成功提示同时有文字、图标与左边框，不单靠颜色区分。
- 切换系统深浅色，确认深色模式下文字、按钮、输入框、错误提示均可读。
- 开启系统「减少动态效果」，确认动画/过渡被降级。

### 8. 回归确认（Stage 7 后）

- 后台计时与离开确认：离开 3 分钟不弹窗继续计时；离开超过阈值返回后弹窗，四选项结算正确（全部计入/不计入/部分/暂停），刷新或重开后未确认弹窗恢复、已确认不重复。
- 批量目标时长解析：中文逗号/顿号/分号/换行/空格/全角数字均可识别，非法值报错带具体值。
- 固定时间冲突检测、自动排期（含固定任务超时补排、任务间 5 分钟缓冲）仍正常。
- 开始 / 暂停 / 继续 / 完成 / 复盘 / 历史功能不受离开确认影响。
- 刷新后数据仍在（localStorage `blockflow.v1`）。

### 9. PWA / 安装到桌面（Stage 8）

> Service Worker 仅在 http/https 安全上下文生效。请用本地服务验证：`python -m http.server 8080` 后访问 `http://localhost:8080/`。

已验证（实测通过）：`http://localhost:8080/` 下 Service Worker 已激活；断网刷新后页面骨架与本地任务数据均正常加载。

1. `file://` 直接双击 `index.html`：页面正常、五页可切换、无白屏；设置页「安装到桌面」面板隐藏；Console 无红色 JS 报错（manifest 加载告警可忽略）。
2. `http://localhost:8080/`：DevTools → Application → Service Workers 显示 `service-worker.js` 已 `activated`；Cache Storage 出现 `blockflow-static-blockflow-v1`，含 index.html / styles.css / app.js / manifest 与图标。
3. 勾选 Offline 后刷新：页面骨架仍加载，本地任务数据仍在。
4. 正常联网下增改任务并刷新：数据不丢失。
5. 把 `service-worker.js` 顶部 `CACHE_VERSION` 改为 `blockflow-v2` 后刷新：旧缓存被清理、新缓存建立，加载最新文件。
6. 支持安装的浏览器会出现地址栏安装图标与设置页「安装到桌面」按钮，点击可弹出安装提示。
7. 回归：执行页开始任务 → 切后台超过阈值返回 → 离开确认弹窗仍正常。

### 10. 数据导入 / 导出（Stage 9）

> 全程本地、不经任何云端。

1. 设置页「数据」面板点「导出数据」：浏览器下载 `blockflow-backup-YYYYMMDD-HHmm.json`，内联提示与 Toast 均显示成功。
2. 点「清空全部数据」：出现二次确认，确认后数据清空并提示。
3. 点「导入数据」，选择刚导出的 JSON：出现覆盖二次确认，确认后数据恢复、页面切到「今日」，提示「导入成功」。
4. 导入一个非法文件（非 JSON 或字段缺失）：显示「导入失败：…（现有数据未改动）」红色提示并滚动到可见区域，现有数据保持不变。
5. 导入失败后刷新页面：确认原有数据仍完整（未被覆盖）。

## 已知限制

- 计时基于时间戳恢复，但应用需处于前台或后台未被浏览器完全冻结；完全关闭标签页期间的离开区间以重新打开时的时间戳计算。
- 数据仅存于本机浏览器，清除浏览器数据会丢失；Service Worker 仅缓存静态资源，不触碰任务数据。
- Service Worker / 安装到桌面仅在 http(s) 下可用，`file://` 下自动跳过（不影响正常使用）。
- PWA 元数据使用固定 `id`、`start_url` 与 `scope`；因未提供真实应用截图，Manifest 暂不包含 `screenshots`（不伪造尺寸，保持基本 Manifest 可用）。
- 不做任务拖拽排序，任务按计划开始时间排序。
